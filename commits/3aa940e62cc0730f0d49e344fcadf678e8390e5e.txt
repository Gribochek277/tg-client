Fix Kitty image display: transmit PNG, not JPEG; transparent bg; PRD folders
Images never rendered because the Kitty graphics protocol only accepts
f=24/32/100 (RGB/RGBA/PNG) — my JPEG (f=101) and WebP (f=103) transmits
were silently rejected by the terminal, leaving blank holes. Now:
- sharp converts every downloaded thumb/preview to PNG at download time
  (cache stores chatId_msgId_x.png; old JPGs convert lazily on cache hit).
- buildTransmit no longer sends a bogus s= (that key is image width, not
  payload size — PNG reads its dimensions from the data).
- Verified end-to-end with a q=0 verbose transmit: terminal answers OK
  for f=100 chunked PNGs (306 chunks through herdr → Ghostty).

UI: backgrounds are transparent now (terminal's own bg/transparency shows
through); the active bg is only on the selected sidebar row and the
message cursor row.

PRD: chat folders moved into M1 (sidebar shows Telegram folders via
messages.getDialogFilters + All chats), split panes removed from M1
rendering.

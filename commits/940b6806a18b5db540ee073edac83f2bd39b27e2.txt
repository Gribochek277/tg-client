Fix layout/scroll breakage when images load
Root cause: the scroll math used rows.length (element count) as the layout
height, but image boxes are single elements spanning several rows — so
maxStart/offset were wrong as soon as any image existed, and grew worse as
photos streamed in.

- Layout now tracks the real height (totalRows = sum of element heights)
  plus each element's start row; the viewport row offset is converted to an
  element index via elemStartRows.
- Photos reserve their final box from the message's own media dimensions
  (width/height are in the media summary), so the layout never changes when
  the download completes — the box shows a dim '📷 loading…' hint until the
  image arrives.
- For the remaining cases (stickers without media dims) a viewport anchor
  pins the top message and adjusts the scroll offset when the layout grows,
  so content stays put.
- Follow-cursor re-anchoring now applies immediately (was off by one frame).

Unit-tested: layout height stable before/after image load; image moves
exactly one row per scroll step; anchor keeps the top message pinned when
a sticker grows the layout.
